# 隐私与公开发布检查

## 本地数据

`config/` 可能包含项目目录、Codex 会话文件路径、SSH 项目标识、自定义标题、隐藏/置顶记录和已查看状态。它是运行时用户数据，不是示例配置。

`.codex/`、`.agents/` 是本地开发上下文；`.local/` 保存历史验证记录和整理前的文档。上述目录全部被忽略并保留在本机，不进入 Git 或便携包。

程序读取当前用户的 Codex 本地会话及索引，提取状态和项目元数据；不会改写会话或将提示词正文保存到自身配置。打开远程项目可能调用已配置的 VS Code SSH 连接。

## 此次整理

- 仓库此前没有提交，因此不存在需要重写的旧提交历史。
- 从提交范围排除运行配置、编辑器上下文、历史验证日志和生成二进制。
- 将历史验证记录归档到忽略的 `.local/verification/`。
- 使用 GitHub noreply 邮箱作为本仓库提交邮箱，避免提交元数据暴露私人邮箱。
- 对计划提交的文本检查常见密钥、令牌和个人用户目录模式；公开文件还需人工复核。

## 提交前检查

```powershell
git status --short
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Check-Public.ps1
git diff --cached --stat
git diff --cached
```

检查脚本读取 Git 索引里的实际内容，而不是只看工作区，发现禁止路径或常见凭据模式会失败；不会打印匹配到的凭据值。它不能保证识别所有敏感信息，请同时检查项目标题、截图、远程地址和新加入的配置文件。

不要用 `git add -f` 添加上述忽略目录。源码 ZIP 请从 Git 标签生成，不要压缩整个工作目录后公开。便携包仅包含程序、分发说明、发布说明、LICENSE、NOTICE 和哈希清单。

如果发现真实密钥已被提交，应先撤销/轮换密钥，再处理 Git 历史；仅删除当前文件无法清除历史版本。
